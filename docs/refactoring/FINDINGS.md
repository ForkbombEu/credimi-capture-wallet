| F-06 | Bug (P2), interoperability | ≈ 0.2 % of generated X.509 certificates carry a non-minimally DER-encoded serial number (`00 xx…`, xx < 0x80). OpenSSL (`node:crypto` `X509Certificate`) rejects it with `illegal padding`. Reproduced deterministically (`/tmp/asn1repro/`), 23/3000 init failures measured. Introduced by `e0ef092`, made visible by `80873ae`. | `src/config.ts:932` (shim), `:873-917` (`writeCertificate`), `:546` (OpenSSL parse); `@peculiar/x509` `x509.es.js:2846-2866` | Return a plain `Uint8Array` from the shim (`new Uint8Array(randomBytes(length))`), optionally validate the verifier certificate with `node:crypto` in `init`; report upstream to `@peculiar/x509` and Credo-TS.
